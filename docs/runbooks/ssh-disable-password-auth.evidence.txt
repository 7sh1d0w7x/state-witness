Operator mistakes during this run, kept because they are the useful part:

1. The step-3 block was first pasted into the operator's own workstation shell,
   not into the VM. Nothing broke (sshd was inactive there, the file ended up
   empty), but for a few minutes the change "didn't work" for a reason that had
   nothing to do with sshd. Check the prompt before pasting a block.
2. Pasting a multi-line block (`printf … | sudo tee …` followed by more commands)
   interleaved the lines: the file was created empty and `sshd -t` still passed,
   because an empty drop-in is valid. One line at a time is slower and safer.
3. Two `grep` invocations used misspelled keys (`passwordautenthication`,
   `kdbinteractauthentication`) and printed nothing. Empty output from a
   command whose key does not exist looks exactly like a broken system.
